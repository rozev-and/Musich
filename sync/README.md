# musich-sync

Клиент синхронизации MUSICH: держит «папку синхронизации» на устройстве в согласии с сервером.
Работает по контракту [`docs/API.md`](../docs/API.md). Решения там, где контракт молчит, записаны
в [`CONTRACT-NOTES.md`](CONTRACT-NOTES.md).

- Новый файл в папке (когда перестал расти) → sha256 → `HEAD /api/tracks/by-hash/:id` → при необходимости `POST /api/tracks`.
- Новый трек на сервере → скачивается во временный `.<id>.musich-part` рядом и переименовывается в `Артист - Название.формат`.
  Существующие файлы не затираются (будет `… (2).mp3`). После обрыва докачивается через `Range`.
- Трек удалили из хранилища (надгробие) → локальный файл удаляется.
- Файл удалили из папки руками → «удалено только здесь»: сервер не трогаем и обратно не качаем.
- Ошибки сети и 5xx → повтор с растущей паузой; если сеть так и не появилась, следующий проход продолжает с того же курсора.

Node 22+, без зависимостей в рантайме (только `typescript` и `@types/node` для сборки).

## Установка на ПК

```powershell
cd C:\path\to\MUSICH\sync
npm install
npm run build
npm link            # появится команда musich-sync (или запускайте: node dist\src\cli.js ...)
```

## Настройка

```powershell
musich-sync init --server http://192.168.1.10:2290 --folder "C:\Users\you\Music\Musich" --name "Домашний ПК"
```

Флаги `init`:

| Флаг | Что это |
|---|---|
| `--server` | адрес сервера без `/api` |
| `--folder` | папка синхронизации (создаётся, если нет) |
| `--name`, `--kind` | имя устройства и тип: `desktop` / `laptop` / `phone` |
| `--token` | токен устройства: создаётся в веб-морде сервера (можно передать и переменной окружения `MUSICH_TOKEN`) |
| `--mode` | `all` — качать всё (по умолчанию), `on-demand` — только по `musich-sync pull <id>` |
| `--poll` | как часто `watch` спрашивает сервер, секунд (по умолчанию 30) |

`init` можно запускать повторно, чтобы поменять отдельные настройки: остальные сохранятся, `deviceId`
останется прежним, пока не сменится сервер. Смена сервера или папки сбрасывает состояние синхронизации.

## Команды

```powershell
musich-sync run                              # один проход
musich-sync watch                            # демон: следит за папкой + опрос сервера (Ctrl+C — стоп)
musich-sync status                           # сервер, курсор, что ждёт загрузки/скачивания
musich-sync status --json
musich-sync remove 3f9a1c0b2d4e5f60 --local      # убрать только с этого устройства
musich-sync remove "Кино - Группа крови.flac" --everywhere   # удалить из хранилища везде
musich-sync pull 3f9a1c                      # скачать по запросу / вернуть «удалённое только здесь»
```

Вместо id можно указать путь к файлу в папке или начало id (от 4 символов, если оно однозначно).
`-v` — подробный лог.

## Где лежит состояние

`%APPDATA%\musich` на Windows, `$XDG_CONFIG_HOME/musich` или `~/.config/musich` в остальных системах.
Переменная `MUSICH_CONFIG_DIR` переопределяет путь (так работают тесты).

- `config.json` — сервер, токен, `deviceId`, папка, режим, интервалы. Можно править руками:
  `stableMs` (сколько файл не должен меняться, по умолчанию 2000), `retries` (5), `retryDelayMs` (1000).
- `state.json` — курсор `seq`, карта `путь → {id, size, mtime}`, список «удалено только здесь»,
  каталог доступных на сервере треков. Пишется атомарно (временный файл + rename).
- `sync.lock` — пока идёт проход; `run`/`remove`/`pull` подождут, если `watch` занят.

## Автозапуск на Windows (по желанию)

```powershell
schtasks /Create /SC ONLOGON /TN "MUSICH sync" /TR "\"C:\Program Files\nodejs\node.exe\" \"C:\path\to\MUSICH\sync\dist\src\cli.js\" watch"
```

## Разработка

```powershell
npm run build   # tsc → dist/
npm test        # сборка + node --test
```

Тесты поднимают фейковый сервер в памяти ([`test/fake-server.ts`](test/fake-server.ts)) на случайном
порту `127.0.0.1` и работают только во временных папках: загрузка, дедупликация, скачивание и имена,
надгробия, ручное удаление, переименование, `remove`/`pull`, режим on-demand, обрыв сети и докачка
через `Range`, `watch` и сквозной прогон CLI.
