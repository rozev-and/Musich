# Несколько пользователей на сервере

Решено с владельцем 2026-11-25. Это договор между сервером (`server/`) и интерфейсом (`web/`): обе стороны делаются по нему одновременно.

## Что решили

| Вопрос | Решение |
|---|---|
| Что такое аккаунт | **Всё раздельно** (как Immich): у каждого своя музыка, лайки, плейлисты, история, обложки, корзина, конфликты, интеграции, устройства, настройки библиотеки |
| Регистрация | **Свободная, владелец включает**: переключатель «Разрешить регистрацию» в настройках сервера (по умолчанию выключен) |
| Вход | **Логин + пароль**. Логин — латиница, цифры, `.`, `_`, `-`, 3–32 символа, без учёта регистра, уникальный. Имя для показа — отдельно (профиль) |
| Аккаунтов на телефоне | **Один**. Сменить — выйти и войти другим |
| Папки с музыкой на диске | **Владелец назначает**: у каждой папки есть хозяин-пользователь; одна папка — одному пользователю. Загруженное с телефона/сайта кладётся в `<папка загрузок>/<логин>/` |
| Один файл у двух людей | **Два отдельных файла**: у каждого своя копия на диске и своя запись |
| Права владельца | список пользователей (логин, имя, когда заходил, сколько треков и места), **сброс пароля**, **удаление** (с его музыкой), **просмотр чужой библиотеки** (только чтение) |
| Нынешние данные | всё, что есть сейчас, — **владельцу**. После обновления сервер просит владельца придумать логин (пароль прежний) |

## Сервер: данные

- Таблица `users`: `id` (uuid), `login` (уникальный, `COLLATE NOCASE`), `name`, `email`, `avatar`, `password` (scrypt, как сейчас), `role` (`owner` | `user`), `created_at`, `last_seen_at`. Владелец ровно один.
- Миграция: создаётся владелец с `login = NULL` (его придумывают при первом входе), паролем из `settings.password` и профилем из нынешнего профиля. Всем строкам пользовательских таблиц ставится `user_id` владельца.
- `user_id` — в таблицах: `tracks`, `likes`, `playlists`, `plays`, `covers`, `trash`, `conflicts`, `hashes`, `devices`, `folders`, `tokens`, `events` и `journal_pending` (журнал синхронизации — у каждого пользователя свой). Настройки, которые сейчас общие (`prefs`, `dupIgnored`, `integration:*`), становятся пользовательскими: ключ с суффиксом `:<userId>` (или своя таблица).
- **id трека.** Сейчас `id` = первые 16 hex sha256 файла, и он глобально уникален. Чтобы не менять первичные ключи везде: у владельца id остаётся прежним (sha256 файла), у остальных — 16 hex от `sha256(userId + ':' + sha256 файла)`. `hash` (нынешний отпечаток файла) хранится как есть, поиск по отпечатку (`/tracks/by-hash`, «файл уже есть») — только среди треков этого пользователя.
- `seq` (курсор `/changes`) остаётся общим счётчиком; выдача фильтруется по пользователю.
- Скан папки: треки получают `user_id` хозяина папки. Загрузка: файл — в `<uploads>/<login>/`, трек — тому, кто загрузил.
- Пользователь видит и меняет только своё: каждый запрос по id чужого трека, плейлиста, устройства и т. п. — **404**.

## Сервер: API

Вход и регистрация (без токена):

- `GET /api/auth/status` → `{ setupDone, authenticated, registration: boolean, ownerNeedsLogin: boolean, user?: { id, login, name, role } }`. `ownerNeedsLogin` — владелец есть, логина у него ещё нет (после обновления).
- `POST /api/auth/setup` `{ login, password, name? }` — первый запуск, создаёт владельца → `{ token, user }`. Уже настроен — 409.
- `POST /api/auth/claim` `{ login, password }` — владелец после обновления: проверяет нынешний пароль, задаёт логин → `{ token, user }`.
- `POST /api/auth/login` `{ login, password, name? }` (`name` — подпись входа/устройства, как сейчас) → `{ token, user }`. Неверно — 401.
- `POST /api/auth/register` `{ login, password, name? }` → `{ token, user }`. Регистрация выключена — 403 `registration_closed`; логин занят — 409 `login_taken`; плохой логин — 400. Пароль — не короче 8 символов (как сейчас).
- `POST /api/sync/pair` (вход по коду) выдаёт токен **того пользователя**, кто создал код.

С токеном:

- `GET/PUT /api/profile` — свой профиль (`login` только читается).
- `PUT /api/auth/password` — свой пароль (как сейчас).
- Всё остальное (`/tracks`, `/changes`, `/playlists`, `/plays`, `/devices`, `/folders`, `/trash`, `/conflicts`, `/stats`, `/prefs`, `/integrations/*`, `/sync/*`, `/covers/*`) — в пределах своего пользователя.

Только владелец (остальным 403):

- `GET /api/users` → `[{ id, login, name, role, createdAt, lastSeenAt, tracks, bytes }]`.
- `PUT /api/users/:id/password` `{ password }` — новый пароль; все входы этого пользователя сбрасываются.
- `DELETE /api/users/:id` — удалить пользователя, его записи и **его файлы** (папка загрузок `<uploads>/<логин>/`; файлы в назначенных ему папках с диска **не удаляются**, только записи). Себя удалить нельзя.
- `GET /api/server/settings` → `{ registration }`, `PATCH /api/server/settings` `{ registration }`.
- Папки: `GET /api/folders` у владельца возвращает все папки с полем `userId`; `POST /api/folders` `{ path, userId? }` (по умолчанию себе); `PUT /api/folders/owner` `{ path, userId }` — передать папку другому (её треки переезжают к нему). У остальных `GET /api/folders` — только свои, менять нельзя.
- Бэкап и восстановление, `/api/fs`, `/api/scan` — только владелец.
- **Просмотр чужой библиотеки:** владелец шлёт заголовок `X-Musich-As: <userId>` — запросы на чтение (`GET`) отвечают от имени этого пользователя; любой не-`GET` с этим заголовком — 403. Заголовок от не-владельца — 403. CORS: заголовок добавить в `Access-Control-Allow-Headers`.

## Интерфейс (`web/`)

- Вход: логин + пароль. Ссылка «Регистрация», если `registration` включена: логин, имя, пароль, повтор. Первый запуск сервера: логин, имя, пароль, повтор — это владелец. Владелец после обновления (`ownerNeedsLogin`): «Придумайте логин» + нынешний пароль → `/auth/claim`.
- Телефон, форма «Свой сервер» (`views/AuthScreen.tsx`, `store.signInServer`): логин + пароль; переключатель «Войти / Регистрация» (регистрация — если сервер разрешает); новый сервер — создание владельца. Вход по коду — как сейчас.
- «Аккаунт»: показывать логин (не меняется), имя, почту, фото, смену пароля.
- Настройки сервера (только владелец), раздел «Пользователи»: переключатель «Разрешить регистрацию»; список пользователей (логин, имя, когда заходил, треков, место); у каждого — «Сбросить пароль» (окно с новым паролем), «Удалить» (подтверждение: удалится его музыка из папки загрузок), «Открыть библиотеку».
- «Папки с музыкой» у владельца: у каждой папки — чья она (выбор пользователя), при добавлении — выбор пользователя.
- «Открыть библиотеку» пользователя: всё приложение переходит в режим просмотра — все запросы с `X-Musich-As`, сверху плашка «Библиотека <имя> — только просмотр» и «Выйти из просмотра»; правки (лайк, плейлисты, удаление, загрузка) недоступны.
- Тексты — на 8 языках (`web/src/i18n/*.ts`: ru en it de fr ar zh ja).

## Сделано (2026-11-25)

Интерфейс — вход/регистрация/«Придумайте логин», раздел «Пользователи», хозяева папок, режим просмотра. Рабочая база перенесена; копия до переноса — `server/.local/data/musich.before-users.db`.

Уточнения к договору, как сделано на сервере:
- коды ошибок: плохой логин — 400 `bad_login`, короткий пароль — 400 `bad_request`, повторный setup или claim — 409 `conflict`, вход до создания владельца — 409 `setup_required`;
- вход одним паролем (без логина) пускает как владельца — для старых версий приложения;
- `?as=<userId>` в адресах файлов и картинок работает как `X-Musich-As` (картинки и звук не умеют слать заголовки);
- `PUT /api/folders/owner` переносит треки папки новому хозяину пересканированием: у прежнего лайки и правки этих треков не переезжают;
- удаление пользователя стирает его папку загрузок; файлы назначенных ему папок остаются на диске;
- `rescanMinutes` и `watch` в настройках библиотеки — общие для сервера (меняет владелец);
- логин, совпадающий с уже существующей папкой в загрузках, считается занятым.
