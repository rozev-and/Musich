# MUSICH — полное руководство

Как поставить MUSICH, как им пользоваться и как он устроен внутри.
Первая часть — для людей. Вторая («Для разработчиков и ИИ») — сжатый контекст, чтобы человек или нейросеть
могли сразу работать с кодом, не перечитывая весь проект.

Связанные документы: [API](API.md) · [Синхронизация](SYNC.md) · [Пользователи](USERS.md) · [Windows](../deploy/windows/README.md)

---

## Часть 1. Пользователю

### 1. Что такое MUSICH

MUSICH — свой музыкальный сервис, как Immich, только для музыки. Три части на одном коде:

| Часть | Что делает | Где работает |
|---|---|---|
| **Сервер** | Хранит музыку, теги, обложки, плейлисты, историю, аккаунты. Раздаёт веб-версию | Docker (Linux, Raspberry Pi), Windows-установщик или просто Node |
| **Веб-версия** | Полный интерфейс в браузере | Любой браузер, адрес сервера, порт `2290` |
| **Приложение для Android** | Своя копия библиотеки на телефоне, играет без сети | Телефон; с сервером или полностью автономно |

Главные идеи:
- **Музыка твоя.** Файлы лежат на твоём диске, MUSICH их не прячет и не переупаковывает.
- **Local-first.** Каждое устройство работает само. Когда устройства видят друг друга, изменения сливаются.
- **Всё настраивается в интерфейсе.** Конфигов и `.env` для работы не нужно.

### 2. Установка сервера

Выбери один способ.

#### 2.1. Docker (Linux, NAS, Raspberry Pi 4/5)

```bash
git clone https://github.com/rozev-and/Musich.git && cd Musich
mkdir -p music data          # заранее, иначе Docker создаст папки от root
docker compose up -d --build
```

Открой `http://<адрес-сервера>:2290`.

Что можно поменять (необязательно, через `.env` рядом с `docker-compose.yml`, образец — `.env.example`):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `MUSICH_PORT` | `2290` | порт на хосте |
| `MUSICH_BIND` | `0.0.0.0` | `127.0.0.1`, если наружу только через nginx |
| `MUSICH_UID` / `MUSICH_GID` | `1000` | под кем работает процесс — владелец папок с музыкой |
| `MUSIC_PATH` | `./music` | первая папка с музыкой |
| `DATA_PATH` | `./data` | база SQLite, обложки, миниатюры |
| `TZ` | `Europe/Moscow` | часовой пояс |

Диски хоста `/mnt` и `/media` уже проброшены в контейнер: папки на них выбираются прямо в интерфейсе.
Образ собирается под `amd64` и `arm64`.

Обновление: `git pull && docker compose up -d --build`. Данные в `data/` сохраняются.

#### 2.2. Windows без Docker

Установщик `MUSICH-Setup-<версия>.exe`: «Далее → Готово», и в браузере открывается MUSICH.

- Программа: `C:\Program Files\MUSICH` (свой Node внутри).
- Данные: `C:\ProgramData\MUSICH\data`, первая папка музыки — `C:\ProgramData\MUSICH\music`, журнал — `…\logs\musich.log`.
- Сервер стартует вместе с Windows (задача планировщика `MUSICH`) и поднимается сам, если упал.
- Брандмауэр открыт только для домашней и рабочей сети. Если телефон не видит сервер — переключи сеть Windows на «Частную».
- Удаление программы не трогает данные и музыку.

Подробнее и сборка установщика — [deploy/windows/README.md](../deploy/windows/README.md).

#### 2.3. Свой сервер плейбуком Ansible

Роль `deploy/roles/musich` ставит Docker, каталоги, compose, собирает образ и проверяет здоровье.
Свой сервер с доменом — за nginx или другим прокси с https: MUSICH сам узнает свой домен.

#### 2.4. Доступ из интернета

MUSICH сам не открывает порты и не использует туннели. Хочешь доступ снаружи — поставь перед ним свой
reverse-proxy (nginx, Caddy) с HTTPS. Внутри MUSICH уже есть защита входа: 5 неверных паролей с одного адреса
за 15 минут — блок на 15 минут.

### 3. Первый запуск

1. Открой `http://<адрес>:2290`. Сервер новый — MUSICH попросит **создать аккаунт владельца**: имя, логин, пароль.
2. **Настройки → Папки с музыкой** — добавь папки, где лежат твои файлы. MUSICH просканирует их сам.
3. Дальше MUSICH следит за папками: новый файл появляется в библиотеке через пару секунд, плюс страховочный
   скан раз в час.

Поддерживаются обычные аудиофайлы (mp3, flac, m4a, ogg, opus, wav и другие). Теги и обложки читаются из файлов.

### 4. Телефон (Android)

#### Установка и вход
Поставь APK. При первом запуске два пути:

- **Подключить сервер.** Телефон сам ищет сервер в домашнем Wi‑Fi (или введи адрес вручную). Когда сервер
  найден, выбери способ входа:
  - **Логин и пароль**;
  - **Код с устройства** — на уже подключённом устройстве открой «Аккаунт → Устройства → Подключить устройство»,
    там 6 цифр (и QR). Код живёт 10 минут и работает один раз.
- **Начать без сервера.** Только имя — и приложение работает автономно. Сервер можно привязать потом:
  «Настройки → Синхронизация → Сервер». При привязке откроется окно «Объединить»: библиотеки телефона и
  сервера сольются.

#### Как телефон держит музыку
- На телефон качается: **«Избранное»**, плейлисты с включённым **«Держать на устройстве»** и то, что скачал вручную.
  Или всё — «Настройки → Синхронизация → Что держать на телефоне».
- «Только по Wi‑Fi» и «Лимит места» — там же.
- Без сети всё работает: играет скачанное, лайки, плейлисты и прослушивания копятся и уходят на сервер,
  когда он доступен. Значок «не в сети» в шапке — нажми, чтобы поискать сервер сейчас.
- **Где хранить музыку:** «Папка: стандартная / своя» и «После удаления приложения: не трогать / удалить».
  Со стандартной папкой и «не трогать» файлы лежат в общей «Музыка/MUSICH» и переживают переустановку.
- **Добавить музыку с телефона:** кнопка «Добавить музыку» или «Поделиться → MUSICH» из любого приложения.
  Файл копируется в приложение и уходит на сервер (без сети — в очередь).

#### Удобства телефона
- Управление из шторки и с экрана блокировки, виджет на главный экран.
- Пауза, когда отключаешь наушники.
- **Экономия заряда** (авто — при заряде меньше 20%): меньше эффектов, реже связь с сервером, загрузки ждут зарядки.
- **PIN-код** — «Настройки → Защита».

### 5. Интерфейс по разделам

Меню (на ПК слева, на телефоне снизу — набор кнопок настраивается):

| Раздел | Что там |
|---|---|
| **Главная** | Что играет, свежее, «Избранное», сводка библиотеки, устройства и лента «что приходило» |
| **Треки** | Вся библиотека. Поиск, «Фильтры и порядок» (показать, файл, год), выделение пачкой, перетаскивание |
| **Альбомы** | Альбомы из тегов и вкладка **«Мои»** — свои плейлисты, «Избранное», умные плейлисты, импорт `.m3u` |
| **Артисты** | Все артисты; у артиста — его треки и кнопка «Радио» |
| **История** | Сверху **«Итоги»** (месяц/год), ниже все прослушивания и график активности |
| **Сервер / Синхронизация** | На сервере — диск, скан, устройства, «Конфликты» и дубли. На телефоне — статус синхронизации |
| **Интеграции** | Плейлисты Spotify, YouTube Music, Шмяндекс, VK и чего из них нет в библиотеке |
| **Корзина** | Удалённое (на сервере), можно вернуть |
| **Настройки** | См. раздел 7 |

**Поиск:** на ПК — поле над списком, на телефоне — лупа, открывает общий поиск по трекам, альбомам и артистам.

### 6. Как сделать…

#### Плеер
- **Перелистнуть трек** — свайп по обложке (на телефоне) или кнопки.
- **Очередь** — кнопка списка в плеере; порядок меняется перетаскиванием за ручку.
- **Перемешать / Повтор** — кнопки по краям.
- **Таймер сна** — плитка под плеером: циферблат, ведёшь точку пальцем (до 2 часов) или «До конца трека».
- **Поделиться** — отправляет сам файл трека (Telegram, почта…). Нет файла на телефоне — скачает с сервера.
- **Текст песни** — кнопка в плеере (на телефоне в «⋯»). Берётся из тегов файла или из `.lrc` рядом с файлом;
  с метками времени текущая строка подсвечивается.
- **Радио** — «Радио по треку» в меню трека или «Радио» у артиста: бесконечный поток похожего с учётом истории.

#### Библиотека
- **Лайк** — сердечко. Всё лайкнутое — в «Избранном».
- **Плейлист** — «Альбомы → Мои → +», добавить треки: «В плейлист», выделением пачкой или перетаскиванием на
  плейлист в боковой панели.
- **Умные плейлисты** собираются сами: «Добавлено за месяц», «Любимое за год», «Давно не слушал».
- **Импорт** — плитка «Импорт .m3u» в «Моих»; в списках интеграций — «Сохранить как плейлист».
- **Общий плейлист** — поделиться плейлистом с другим пользователем этого же сервера.
- **Править теги** — меню трека → «Изменить». Обложка — нажми на картинку трека, альбома или артиста.
- **Удалить** — с телефона («убрать с устройства», файл остаётся на сервере) или из библиотеки (в корзину).
- **Дубли** — «Сервер → Конфликты»: возможные дубли с битрейтом, метка «лучше», «Оставить лучший» или
  «…во всех» (лайк переносится). «Это разные треки» — больше не предлагать.

#### Итоги
«История» → блок «Итоги»: часы и прослушивания, новые артисты, когда ты слушаешь, топ треков/артистов/альбомов.
«Поделиться» рисует карточку 1080×1350 в цветах твоей темы.

### 7. Настройки

Набор разделов зависит от устройства: часть есть только на сервере (веб), часть — только на телефоне.

| Раздел | Пункты |
|---|---|
| **Внешний вид** | Режим (светлый/тёмный/авто), Тема, Акцентный цвет, Цвет выделения, Цвет блоков, Скругление, Прозрачность блоков, Шрифт, Язык. Тема и шрифт выбираются в окне с примером и применяются кнопкой «Применить» |
| **Интерфейс** | Стартовая страница, Колонки в списках, Анимации, Масштаб, нижняя панель телефона |
| **История** | Засчитывать прослушивание (5/10/30 с или половина трека), Не записывать историю, Last.fm / ListenBrainz |
| **Библиотека** *(сервер)* | Как сохранять правки, Номер новым трекам, Сдвигать номера при удалении, Несколько артистов (разделители), Следить за папками, Пересканировать, Хранить в корзине |
| **Правка треков** *(телефон с сервером)* | Как сохранять правки |
| **Пользователи** *(владелец/админ)* | Разрешить регистрацию, Аккаунты, роли |
| **Бэкап и выгрузка** *(владелец)* | Бэкап базы, Восстановить из бэкапа, Выгрузить музыку (zip) |
| **Воспроизведение** | Кроссфейд, Выравнивать громкость, Когда очередь доиграла (стоп/повтор/радио), Продолжать длинные треки, Горячие клавиши, Качество стриминга |
| **Синхронизация** *(телефон)* | Сервер, Что держать на телефоне, Только по Wi‑Fi, Лимит места, Где хранить музыку, Экономия заряда, Защита (PIN) |

#### «Как сохранять правки»
Два независимых выбора:
- **Теги:** «Только в MUSICH» (файл не меняется) / «Теги в файле» / «Теги и имя файла» (переименует в «Артист - Название»).
- **Картинки:** «Только в MUSICH» / «Вшивать в файлы» (обложка трека — в его файл, обложка альбома — во все его треки).

Лайки, плейлисты и история при правке не теряются: id трека постоянный.

#### Качество стриминга
«320 / 128 kbps» сжимает музыку на лету, если на сервере есть ffmpeg. Без ffmpeg музыка играет в оригинале.

### 8. Несколько пользователей

- Роли: **владелец** (один), **администраторы**, **пользователи**.
- У каждого своя библиотека, лайки, плейлисты, история. Общие — только плейлисты, которыми поделились.
- Регистрацию включает владелец («Пользователи → Разрешить регистрацию»), по умолчанию она выключена.
- Папки на диске назначает владелец или админ: одна папка — одному пользователю. Загрузки — в `<uploads>/<логин>/`.
- Владелец и админы могут смотреть чужую библиотеку (только чтение), сбрасывать пароли, удалять аккаунты.
- Передать владение может только владелец (нужен его пароль), прежний владелец становится админом.

Подробно — [USERS.md](USERS.md).

### 9. Бэкап и перенос

- **Бэкап базы** — один `.db` файл: вся база плюс свои картинки. Музыку он не содержит.
- **Восстановить** — загрузить этот файл; сервер перезапустится с ним (прежняя база останется рядом как `musich.db.before-restore`).
- **Выгрузить музыку** — zip: всё, альбомы или плейлисты; плейлисты — папками или одной папкой + `.m3u`.
- **Переезд на другой сервер:** бэкап базы + копия папок с музыкой → на новом сервере восстановить бэкап и
  указать те же папки.

### 10. Если что-то не так

| Проблема | Что сделать |
|---|---|
| Телефон не находит сервер | Одна сеть Wi‑Fi? На Windows сеть должна быть «Частной». Введи адрес вручную: `192.168.x.x:2290` |
| «Сервер не отвечает» | Проверь, что сервер запущен: `GET /api/health` должен ответить |
| Трек не появился | «Настройки → Библиотека → Пересканировать»; проверь, что папка добавлена и у процесса есть доступ |
| Вход заблокирован | 5 неверных паролей → подожди 15 минут |
| Забыл пароль владельца | На сервере: `server/reset-password.ts` (сброс пароля владельца из консоли) |
| Обложки не видны без сети | Открой приложение с сетью один раз — обложки кэшируются на телефоне |

## Часть 2. Для разработчиков и ИИ

### 11. Архитектура в двух словах

```
            ┌──────────── сервер (Node, Fastify, node:sqlite) ─────────────┐
 файлы  ──► │ скан/слежка → таблица tracks; журнал событий; API /api/*     │ ──► web/dist (раздаёт с /)
            └──────────────────────────────────────────────────────────────┘
                  ▲  /api/changes, /api/sync/pull|push            ▲
                  │                                               │
        веб (host-режим, браузер)                    телефон (device-режим, Capacitor)
                                                     своё зеркало, журнал, файлы, Outbox
```

- **Один код интерфейса, два режима** — `web/src/mode.ts`: `isHost` (веб-версия с сервера) и device (APK).
  Сборка телефона: `vite build --mode device --outDir dist-app`.
- **Сервер — источник правды**, но телефон может работать без него (автономный узел со своим журналом).
- **Синхронизация** — журнал событий с гибридными часами (HLC), обмен по «вектору»; правила слияния и
  конфликты — [SYNC.md](SYNC.md).

### 13. Ключевые понятия

- **id трека постоянный:** отпечаток файла при первом появлении. Правка тегов меняет `hash`, но не `id`.
  `Track.fileChanged` = файл отличается от исходного. У не-первого пользователя id = `sha256(userId:sha файла)`.
- **Надгробие** — запись удалённого трека; `replacedBy` указывает, куда переехал.
- **Outbox** — очередь файлов, добавленных на телефоне и ещё не отправленных (`up:`-id до отправки).
- **Зеркало (mirror)** — копия ответа `/changes` на телефоне для работы без сети.
- **Журнал телефона** — события лайков/плейлистов/правок, когда нет сервера или идёт объединение.
- **`conn`** в сторе — состояние связи: `checking / connect / login / setup / claim / profile / online / local / offline`.
- **Роли:** `owner | admin | user`; просмотр чужой библиотеки — заголовок `X-Musich-As` (только чтение).
- **Настройки:** серверные (в `/api/prefs`, общие для устройств аккаунта) и локальные устройства (тема, плеер — в localStorage, на телефоне дублируются в Preferences).

### 14. Разработка

cd server && npm install && npm run dev   # API на 127.0.0.1:2290
cd web && npm install && npm run dev      # http://127.0.0.1:5173, /api проксируется на 2290

- Типы веба: `npx tsc --noEmit -p .` (в `web/`). **Не запускать `tsc -b`** — он кладёт `.js` рядом с исходниками, и Vite берёт их вместо `.ts`.

### 15. Правила проекта (важно для ИИ)

1. **Всё настраивается в интерфейсе.** Не добавлять настроек через `.env` или конфиги для пользователя.
2. **Тексты интерфейса:** коротко, по-человечески, на «ты», сразу на всех 8 языках (`web/src/i18n/`).
